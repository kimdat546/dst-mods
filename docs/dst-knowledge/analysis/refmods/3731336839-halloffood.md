# Hall of Food (kyno, MOD ID: 3731336839) - Architecture Study

A comprehensive 486-file DST food/cultivation mod showing industrial-scale item, recipe, and world-spawn registration patterns for 300+ edible items and 100+ recipes.

---

## 1. Edible/Consumable Item Prefabs

### 1.1 Core Edible Component Setup Pattern

**File:** `scripts/prefabs/k_banana.lua:93-102`
```lua
inst:AddComponent("edible")
inst.components.edible.healthvalue = TUNING.KYNO_BANANA_HEALTH
inst.components.edible.hungervalue = TUNING.KYNO_BANANA_HUNGER
inst.components.edible.sanityvalue = TUNING.KYNO_BANANA_SANITY
inst.components.edible.foodtype = FOODTYPE.VEGGIE
```
**Pattern:** Health/hunger/sanity restore are set via tuning constants. Foodtype controls NPC diet compatibility. No on-eat callbacks at prefab level (handled by recipe registration instead).

### 1.2 Perishable Component for Food Decay

**File:** `scripts/prefabs/k_banana.lua:99-102`
```lua
inst:AddComponent("perishable")
inst.components.perishable:SetPerishTime(TUNING.PERISH_MED)
inst.components.perishable:StartPerishing()
inst.components.perishable.onperishreplacement = "spoiled_food"
```
**Pattern:** All food items use standardized perish times (PERISH_MED, PERISH_FAST, PERISH_SLOW). onperishreplacement always "spoiled_food" for vanilla items; custom prefabs could differ.

### 1.3 Stackability for Inventory Efficiency

**File:** `scripts/prefabs/k_coffeebeans.lua:54-55`
```lua
inst:AddComponent("stackable")
inst.components.stackable.maxsize = TUNING.STACK_SIZE_SMALLITEM
```
**Pattern:** Stackable items use STACK_SIZE_SMALLITEM (8 units). Prefabs without stacking (e.g., cooked meals) omit this component.

### 1.4 Inventory Item Naming & Atlas Binding

**File:** `scripts/prefabs/k_banana.lua:107-109`, `k_coffeebeans.lua:57-59`
```lua
inst:AddComponent("inventoryitem")
inst.components.inventoryitem.atlasname = "images/inventoryimages/hof_inventoryimages.xml"
inst.components.inventoryitem.imagename = "kyno_banana"
```
**Pattern:** Custom atlasname points to mod's centralized atlas file. imagename must match a sprite name in that atlas (e.g., "kyno_banana" for raw, "kyno_banana_cooked" for cooked variant). Consistent naming is critical; mismatch = missing sprites in inventory.

### 1.5 Cookable Component for Stove Conversion

**File:** `scripts/prefabs/k_banana.lua:111-112`, `k_coffeebeans.lua:61-62`
```lua
inst:AddComponent("cookable")
inst.components.cookable.product = "kyno_banana_cooked"
```
**Pattern:** Raw items link to cooked prefab via cookable.product. Cooked variant is a separate prefab (no cookable component). Both share the same anim bank/build but use different animations (idle vs. cooked).

### 1.6 Multiple Item Variants from Single File

**File:** `scripts/prefabs/k_banana.lua:180-182`
```lua
return Prefab("kyno_banana", banana, assets, prefabs),
Prefab("kyno_banana_cooked", banana_cooked, assets, prefabs),
MakePlacer("kyno_banana_placer", "kyno_bananatree_sapling", "kyno_bananatree_sapling", "planted")
```
**Pattern:** One file exports multiple prefabs (raw, cooked, placer). Assets are shared. Prefabs subtable references dependencies (e.g., "kyno_banana_cooked" spawned by cookable component).

## 2. Cook-Pot / Crafting Recipe Registration

### 2.1 Recipe Data Structure (Test Function Pattern)

**File:** `scripts/hof_foodrecipes.lua:1-23` (coffee recipe)
```lua
local kyno_foods = {
    coffee = {
        test = function(cooker, names, tags)
            return names.kyno_coffeebeans_cooked == 4 
            or (names.kyno_coffeebeans_cooked == 3 and (tags.dairy or tags.sweetener or tags.sugar))
            and not names.kyno_coffeebeans
        end,
        priority = 30,
        foodtype = FOODTYPE.GOODIES,
        perishtime = TUNING.PERISH_MED,
        temperature = TUNING.HOT_FOOD_BONUS_TEMP,
        health = 5, hunger = 9.375, sanity = -10,
        cooktime = 0.5,
        potlevel = "low",
        card_def = {ingredients = {{"kyno_coffeebeans_cooked", 3}, {"honey", 1}}},
    },
}
```
**Pattern:** 
- `test(cooker, names, tags)`: Complex ingredient matching by **exact counts** (names.X == N) or **tag thresholds** (tags.Y >= N).
- `priority`: Lower value = earlier evaluation (30 before 1). Prevents accidental greedier recipes stealing ingredients.
- `card_def`: Display-only ingredient list for cookbook.
- `oneat_desc`: STRINGS key for buff description.
- Temperature bonuses (HOT_FOOD_BONUS_TEMP) apply persistent food warming.

### 2.2 Ingredient Tag System (Cooking Foundation)

**File:** `hof_init/foods/hof_cooking.lua:1-120` (ingredient registration)
```lua
AddIngredientValues({"kyno_coffeebeans"}, {seeds = 1}, true)
AddIngredientValues({"kyno_shark_fin"}, {fish = 1})
AddIngredientValues({"kyno_mussel"}, {fish = 0.5, mussel = 1}, true)
AddIngredientValues({"kyno_aloe"}, {veggie = 1, succulent = 1}, true, true)
```
**Pattern:**
- First arg: ingredient prefab names in a table.
- Second arg: tag map {tagname = value, ...}. Values can be fractional; multiple tags per ingredient.
- Third arg (optional): true = perishable. Fourth arg (optional): true = frozen.
- These tags are accumulated by the cooker (names = exact counts, tags = cumulative totals) and matched against recipe `test()` functions.
- 300+ ingredients registered allows thousands of recipe combinations.

### 2.3 Batch Recipe Registration to Multiple Cookers

**File:** `hof_init/foods/hof_cooking.lua:239-250`
```lua
local common_recipes   = require("hof_foodrecipes")
local seasonal_recipes = require("hof_foodrecipes_seasonal")
local item_recipes     = require("hof_foodrecipes_items")
local cookpots = {"cookpot", "portablecookpot", "archive_cookpot", ...}

for _, cooker in pairs(cookpots) do
    for _, recipe in pairs(common_recipes) do
        AddCookerRecipe(cooker, recipe)
    end
end
```
**Pattern:** Recipe tables are flat Lua tables (not singletons per cooker). The same recipe object is registered to multiple cookers via nested loop. AddCookerRecipe handles deduplication.

### 2.4 Recipe Metadata Enrichment

**File:** `scripts/hof_foodrecipes.lua:3430-3436` (post-processing loop)
```lua
for k, recipe in pairs(kyno_foods) do
    recipe.name = k
    recipe.weight = 1
    recipe.overridebuild = recipe.overridebuild or k
    recipe.cookbook_atlas = "images/cookbookimages/hof_cookbookimages.xml"
    recipe.cookbook_tex = k..".tex"
end
return kyno_foods
```
**Pattern:** All recipes enriched in a final loop with:
- `name`: recipe key (becomes unique identifier).
- `weight`: For random selection (rarely != 1).
- `overridebuild`: Anim build for cooked dish appearance; defaults to recipe name if not explicitly set.
- `cookbook_atlas` / `cookbook_tex`: Where the 3D rendered icon comes from.

### 2.5 Custom On-Eat Effects via Buff Prefabs

**File:** `scripts/hof_foodrecipes.lua:77-79` (sharkfinsoup recipe)
```lua
oneatenfn = function(inst, eater)
    OnFoodNaughtiness(inst, eater)
end,
```
**Pattern:** Optional oneatenfn called after eat animation. Also use `prefabs = {"kyno_berserkerbuff"}` to preload buff entities before instantiation, then `eater:AddDebuff()` in the callback.

### 2.6 Seasonally Gated & Warly-Exclusive Recipes

**File:** `hof_init/foods/hof_cooking.lua:239-250` and modmain.lua
```lua
local warly_recipes = require("hof_foodrecipes_warly")
for _, cooker in pairs(cookpots_master) do
    for _, recipe in pairs(warly_recipes) do
        AddCookerRecipe(cooker, recipe)
    end
end
```
**Pattern:** Separate recipe modules (hof_foodrecipes_seasonal.lua, hof_foodrecipes_warly.lua) registered to subsets of cookers. Seasonal recipes can have conditional logic inside the test() function to check TheWorld:GetState():GetCurrentDayTime() or season.

## 3. World Prefab Spawning & Worldgen Integration

### 3.1 Ocean Fish Data Structure

**File:** `hof_init/world/hof_oceanfish_data.lua:1-151` (excerpt)
```lua
local OCEANFISHES = {
    oceanfish_pufferfish = {
        prefab = "oceanfish_pufferfish",
        bank = "kyno_oceanfish_pufferfish",
        build = "kyno_oceanfish_pufferfish",
        weight_min = TUNING.KYNO_OCEANFISH_PUFFERFISH_MIN_WEIGHT,
        weight_max = TUNING.KYNO_OCEANFISH_PUFFERFISH_MAX_WEIGHT,
        walkspeed = TUNING.KYNO_OCEANFISH_PUFFERFISH_WALKSPEED,

```
**Pattern:** Fish defined as large data table with:
- Anim bank/build references.
- Tuning-driven parameters (size, speed, loot drops).
- Cooking loot (what meat drops when killed).
- Edible values applied to dropped meat.
- Tags for dietary restrictions (OMNI, VEGGIE, MEAT, BERRY).

### 3.2 World Room Prefab Placement

**File:** `hof_init/world/hof_worldgen.lua:20-98` (plant room placement)
```lua
local RoomPrefabs = {
```

**Pattern:** Map of ground-spawn prefab names to room types. Worldgen system reads this and places instances in matching room tiles. "kyno_aloe_ground" (the actual spawned object, not the plant) is spawned in "BGGrass" rooms, etc.

### 3.3 Ancient Trees & Custom Tile Constraints

**File:** `hof_init/world/hof_ancienttree_data.lua:7-10`

```lua
AddSimPostInit(function()
```

## 4. Data-Driven Registration at Scale

### 4.1 Tuning Constants Centralization

**File:** `hof_init/misc/hof_tuning.lua:1-100`
```lua
TUNING.KYNO_BANANA_HEALTH = 1
TUNING.KYNO_BANANA_HUNGER = 12.5
TUNING.KYNO_BANANA_SANITY = 0
TUNING.KYNO_BANANA_COOKED_HEALTH = 3
...
TUNING.KYNO_LUCK_HUGE = 0.25
TUNING.KYNO_LUCK_LARGE = 0.20
TUNING.KYNO_LUCK_MEDLARGE = 0.15
...
TUNING.HOF_COOKPOTS = {
    "cookpot", "portablecookpot", "archive_cookpot",
    "kyno_cookware_syrup", "kyno_cookware_small", ...
}
```
**Pattern:** All numeric values (health/hunger/sanity, durations, sizes, luck scaling) are centralized in one file. Prefabs and recipes reference TUNING.CONSTANT_NAME rather than hardcoding. Makes balance tweaking trivial without touching 200+ individual files.

### 4.2 Prefab Loader Pattern

**File:** `hof_init/misc/hof_prefabs.lua:5-250`
```lua
PrefabFiles = {
    "k_animalfeeder",
    "k_antchest",
    "k_antchovy",
    "k_banana",
    "k_bananatree",
    ... (200+ more)
}
```
**Pattern:** Simple list of prefab file names (without "scripts/prefabs/" or ".lua"). DST's engine loads these in order. Each file returns Prefab objects via return statements. No factory functions needed; the list is declarative and scannable.

### 4.3 String Localization Architecture

**File:** `modmain.lua:9-59`
```lua
local hof_init_strings = {
    "hof_strings",
    "hof_strings_scrapbook",
    "hof_strings_skinprefabs",
}
for _, v in pairs(hof_init_strings) do
    require("strings/"..v)
end

local HOF_LOCALIZATION = "vi"
for _, v in pairs(hof_init_strings) do
    _G.pcall(require, "strings/localization_"..HOF_LOCALIZATION.."/"..v)
end
```
**Pattern:** Strings loaded in two passes:
1. Base English strings (always).
2. Localization overrides (Vietnamese "vi" in this case) via pcall (safe if missing).
Each string table is separate, allowing volunteers to translate only one file without touching others.

## 5. Inventory Item Conventions & Atlas Management

### 5.1 Atlas Hierarchy

**File:** `hof_init/misc/hof_recipes.lua:14-19`
```lua
local DefaultAtlas         = "images/inventoryimages.xml"
local DefaultAtlas1        = "images/inventoryimages1.xml"
local DefaultAtlas2        = "images/inventoryimages2.xml"
local ModAtlas             = "images/inventoryimages/hof_inventoryimages.xml"
local CraftingFilterAtlas  = "images/tabimages/hof_tabimages.xml"
```
**Pattern:** 
- Vanilla atlases (DefaultAtlas) used for recipes that produce base-game items.
- Mod atlas (ModAtlas) used for mod items.
- Separate atlases for tabs/UI (CraftingFilterAtlas).
- Recipes reference the appropriate atlas when setting cookbook icons.

### 5.2 Prefab Asset Declaration

**File:** `scripts/prefabs/k_banana.lua:1-9`
```lua
local assets = {
    Asset("ANIM", "anim/kyno_banana.zip"),
    Asset("ANIM", "anim/kyno_bananatree_sapling.zip"),
    
    Asset("IMAGE", "images/inventoryimages/hof_inventoryimages.tex"),
    Asset("ATLAS", "images/inventoryimages/hof_inventoryimages.xml"),
    Asset("ATLAS_BUILD", "images/inventoryimages/hof_inventoryimages.xml", 256),
}
```
**Pattern:**
- ANIM: Zipped animation files.
- IMAGE: Compiled texture (hof_inventoryimages.tex).
- ATLAS: XML mapping sprite names to texture regions.
- ATLAS_BUILD: Mipmapped atlas for lower resolutions (256px variant).
Atlas must exist before prefab loads; built by art pipeline (not Lua).

### 5.3 Inventoryitem.imagename Binding

**File:** `scripts/prefabs/k_banana.lua:108-109`
```lua
inst.components.inventoryitem.atlasname = "images/inventoryimages/hof_inventoryimages.xml"
inst.components.inventoryitem.imagename = "kyno_banana"
```
**Key Pitfall (from team's MVP1 experience):** imagename MUST match a sprite key in the XML. Mismatch causes missing inventory icon or silent fallback. Naming convention: `kyno_<item>` for raws, `kyno_<item>_cooked` for cooked variants. Enforce in code review.

## 6. Custom On-Eat Effects & Food Buffs

### 6.1 Buff Prefab Pattern

**File:** Implied from hof_foodrecipes.lua (e.g., chickeneggstew recipe)
```lua
prefabs = { "kyno_berserkerbuff" },
oneatenfn = function(inst, eater)
    eater:AddDebuff("kyno_berserkerbuff", "kyno_berserkerbuff")
end,
```
**Pattern:**
- prefabs list preloads the buff entity so AddDebuff() doesn't stall the eater.
- oneatenfn called after the eater finishes chewing animation.
- Buff should have limited duration (defined in its component) or stacking rules.

### 6.2 Food Temperature & Nutrient Bonus

**File:** `scripts/hof_foodrecipes.lua:10-14` (coffee recipe)
```lua
temperature = TUNING.HOT_FOOD_BONUS_TEMP,
temperatureduration = TUNING.FOOD_TEMP_BRIEF,
health = 5, hunger = 9.375, sanity = -10,
```
**Pattern:** temperature (e.g., 60 = hot) persists for temperatureduration seconds. Gives player temperature buff upon eat. Not all recipes use this; only purposeful "warming food" recipes set it.

## 7. Integration Entry Points (modmain.lua Sequence)

**File:** `modmain.lua` (orchestration)
```
1. Load strings (hof_strings, character speeches)
2. Load localization overrides (hof_localization_vi/*)
3. Require hof_main (Fish Registry init)
4. Load hof_init/misc/* (tuning, assets, prefabs, skins, recipes, ...)
5. Load hof_init/foods/* (ingredient tags, recipe registration)
6. Load hof_init/world/* (worldgen, ocean fish, tiles, ...)
7. PostInits for NPCs, environments, etc.
```

**Critical:** WorldGen must load AFTER tiles defined but BEFORE worldgen generation happens (check modworldgenmain.lua).

## Summary of Takeaways for tu-tiên Mod

1. **Ingredient Tag System is the Scaling Secret:** Rather than hardcoding recipe logic, register all ingredients via AddIngredientValues({...}, {tag=value, ...}) upfront. Test functions then match tag sums/counts against thresholds. This allows 100+ recipes from 50 ingredients without combinatorial explosion.

2. **Prefab Tuning Constants Separation:** All numeric values (health, hunger, sanity, perish times, luck %) belong in hof_init/misc/hof_tuning.lua, not scattered in 200+ prefab files. One-file balance changes. Both coffee prefab and recipes reference TUNING.KYNO_COFFEEBEANS_HEALTH.

3. **Inventory Atlas Namespacing is Critical:** Single mod atlas (hof_inventoryimages.xml) for all mod items. imagename must match XML sprite keys exactly. Misspellings cause invisible inventory icons. Use prefab code review checklist: "Is atlasname and imagename consistent?" Consistent naming (e.g., kyno_<item>, kyno_<item>_cooked) prevents typos.
