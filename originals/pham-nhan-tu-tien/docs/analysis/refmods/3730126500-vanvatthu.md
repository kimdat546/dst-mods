## 1. Building/Structure Prefab Patterns

### 1.1 Prefab Loader Architecture
**File:** `/atbooks_all_prefab_loader.lua`

The mod uses a centralized prefab loading system with dynamic path resolution:

```lua
local function LoadPrefabChunk(path)
    local chunk = kleiloadlua(path)
    if chunk == nil then
        error("Prefab file not found: " .. path)
    elseif type(chunk) == "string" then
        error("Error loading prefab file " .. path .. ":\n" .. chunk)
    end
    return { chunk() }
end

return function(submod)
    local root = assert(rawget(_G, "ATBOOKS_ALL_ROOT"), "ATBOOKS_ALL_ROOT is missing")
    local prefab_map = assert(rawget(_G, "ATBOOKS_ALL_SUBMOD_PREFABS"), "ATBOOKS_ALL_SUBMOD_PREFABS is missing")
    local prefab_files = assert(prefab_map[submod], "Submod prefab list is missing: " .. tostring(submod))
    local prefabs = {}

    for _, prefab_file in ipairs(prefab_files) do
        local path = root .. submod .. "/scripts/prefabs/" .. prefab_file .. ".lua"
        local loaded_prefabs = LoadPrefabChunk(path)
        for _, prefab in ipairs(loaded_prefabs) do
            if prefab ~= nil then
                table.insert(prefabs, prefab)
            end
        end
    end

    return unpack(prefabs)
end
```

**Key takeaway:** Uses `kleiloadlua()` to dynamically load many prefabs from a manifest list, returning multiple prefabs per file. Excellent for mod scaling.

## 2. Recipe & Crafting Registration

### 2.1 Recipe API Wrapper (07_recipes/00_recipe_api.lua)

The mod provides a clean abstraction over vanilla recipe registration:

```lua
TBAT.RECIPE = Class()

local recipes_index_list = {
    ["building"] = "tbat_recipe_filter_building",
    ["decoration"] = "tbat_recipe_filter_decoration",
    ["item"] = "tbat_recipe_filter_item",
}

function TBAT.RECIPE:AddRecipe(prefab, _Ingredients, tech, data, recipe_filters_or_index)
    local recipe_filters = {}
    
    -- Convert string or table filter spec into uppercase recipe filter names
    if type(recipe_filters_or_index) == "string" then
        local ret_index = recipes_index_list[recipe_filters_or_index] or "tbat_recipe_filter_building"
        table.insert(recipe_filters, string.upper(ret_index))
    elseif type(recipe_filters_or_index) == "table" then
        for k, v in pairs(recipe_filters_or_index) do
            table.insert(recipe_filters, string.upper(v))
        end
    end
    
    -- Handle lost-tech recipes (no deconstruction)
    if TBAT.RECIPE:GetLostTech() == tech then
        data.no_deconstruction = nil
    end
    
    AddRecipe2(prefab, _Ingredients or {}, tech or TECH.NONE, data, recipe_filters)
    RemoveRecipeFromFilter(prefab, "MODS")
end

function TBAT.RECIPE:CreateList(cmd)
    cmd = cmd or { {"log", 2}, {"boards", 2} }
    local ret = {}
    for i, data in ipairs(cmd) do
        table.insert(ret, Ingredient(data[1] or "log", data[2] or 1))
    end
    return unpack(ret)
end
```

### 3.3 Deep Function Hooking (04_origin_components_hook/04_hunter_footprints_hook.lua)

For modifying internal functions not exposed via component APIs:

```lua
local function HookLocalFunction(hunter_instance, target_name, hook_callback, __common_methods)
    if not hunter_instance or type(hunter_instance) ~= "table" then
        print("[tbat][hunter][error] Invalid hunter instance")
        return false
    end
    
    local original_func = nil
    local function find_and_hook(func, target_name, depth)
        local visited_funcs = {}  -- Per-hook visited set to avoid cross-hook pollution
        local function recursive_search(func, target_name, depth)
            if depth > 50 then return false end  -- Depth guard
            if visited_funcs[func] then return false end
            visited_funcs[func] = true

            for i = 1, math.huge do
                local name, value = debug.getupvalue(func, i)
                if not name then break end

                if name == target_name and type(value) == "function" then
                    original_func = value
                    debug.setupvalue(func, i, function(...)
                        return hook_callback(original_func, ...)
                    end)
                    print("[tbat][hunter] ✅ Successfully hooked:", target_name)
                    return true
                elseif type(value) == "function" then
                    if recursive_search(value, target_name, depth + 1) then
                        return true
                    end
                end
            end
            return false
        end
        return recursive_search(func, target_name, depth or 0)
    end
    
    -- Attempt to hook from constructor, then common methods, then all methods
    if hunter_instance._ctor and type(hunter_instance._ctor) == "function" then
        if find_and_hook(hunter_instance._ctor, target_name, 0) then
            return true
        end
    end
    
    -- ... check common methods and public methods
    return false
end

AddComponentPostInit("hunter", function(self) 
    local hunter = self
    HookLocalFunction(hunter, "GetHuntedBeast", function(original_fn, ...)
        local result = original_fn(...)
        if TheWorld.components.tbat_com_hunter_repliacer then
            result = TheWorld.components.tbat_com_hunter_repliacer:GetReplaceMonster(result) or result
        end
        return result
    end)
end)
```

**Critical for world scaling:** Uses `debug.getupvalue/setupvalue` to intercept encapsulated functions. Guards against recursion depth and visited functions to prevent infinite loops.

## 4. Custom Data Components

### 4.1 Universal Data Storage (tbat_data.lua)

A generic key-value component for storing arbitrary persistent data:

```lua
local tbat_data = Class(function(self, inst)
    self.inst = inst
    self.DataTable = {}
    self.TempTable = {}
    self._onload_fns = {}
    self._onsave_fns = {}
    self._on_post_init_fns = {}
end)

function tbat_data:Set(index, theData)
    if index then
        self.DataTable[index] = theData
    end
end

function tbat_data:Get(index, default)
    if index then
        return self.DataTable[index] or default
    end
    return nil or default
end

function tbat_data:Add(index, num, min, max)
    if index then
        if min and max then
            local ret = (self.DataTable[index] or 0) + (num or 0)
            ret = math.clamp(ret, min, max)
            self.DataTable[index] = ret
            return ret
        else
            self.DataTable[index] = (self.DataTable[index] or 0) + (num or 0)
            return self.DataTable[index]
        end
    end
    return 0
end

function tbat_data:OnSave()
    self:ActiveOnSaveFns()
    local data = {}
    for k, v in pairs(self.DataTable) do
        data[k] = v
    end
    return data
end
```

**Reusable pattern:** Generic data persistence without needing prefab-specific components.

### 4.2 Client-Side Data Replica (tbat_com_client_side_data_replica.lua)

Manages data accessible only on client, with server-client synchronization:

```lua
local tbat_com_client_side_data = Class(function(self, inst)
    self.inst = inst
    TBAT:ReplicaTagRemove(inst, "tbat_com_client_side_data")

    if not TheNet:IsDedicated() then
        inst:ListenForEvent("tbat_com_client_side_data.server_ask_data", function(_, cmd)
            local task_id = cmd.task_id
            local index = cmd.index
            local ret_data = self:Get(index)

            local cmd_data = {
                task_id = task_id,
                data_str = TBAT.FNS:ZipJsonStr(json.encode(ret_data)),
            }
            self:GetRPC():PushEvent("tbat_com_client_side_data.answer_server_ask_data", cmd_data)
        end)

        inst:ListenForEvent("tbat_com_client_side_data.server_set_data", function(_, cmd)
            local index = cmd.index
            local value_str = cmd.value_str
            local value = json.decode(value_str)
            self:Set(index, value)
        end)
    end
end)

function tbat_com_client_side_data:Get(index)
    if not TheNet:IsDedicated() then
        return TBAT.ClientSideData:PlayerGet(index)
    end
    return nil
end

function tbat_com_client_side_data:Set(index, value)
    if not TheNet:IsDedicated() then
        TBAT.ClientSideData:PlayerSet(index, value)
        return
    end
    if TheWorld.ismastersim then
        self.inst.components.tbat_com_client_side_data:Set(index, value)
    end
end
```

**Valuable for tu-tiên:** Enables server to request/set client-only data (UI state, preferences, visual effects) without needing dedicated network vars.

### 4.3 Skin Controller Data (tbat_com_skins_controller.lua)

Manages unlocked skins per prefab, synced to player data:

```lua
local tbat_com_skins_controller = Class(function(self, inst)
    self.inst = inst
    self._debug_data_table = {}
    self._onload_fns = {}
    self._onsave_fns = {}
    self._on_post_init_fns = {}

    end)

function tbat_com_skins_controller:GetUnlockedSkinsData()
    return self:Get("unlocked_skins", {}), self:Get("unlocked_skins_ids", {})
end

function tbat_com_skins_controller:SetUnlockedData(prefab, skin_name)
    if type(prefab) ~= "string" or type(skin_name) ~= "string" then
        return
    end
    
    local unlocked_skins, unlocked_skins_ids = self:GetUnlockedSkinsData()
    if not unlocked_skins[prefab] then
        unlocked_skins[prefab] = {}
        unlocked_skins_ids[prefab] = {}
    end
    
    local idx = unlocked_skins_ids[prefab][skin_name]
    if not idx then
        idx = #unlocked_skins[prefab] + 1
        table.insert(unlocked_skins[prefab], skin_name)
        unlocked_skins_ids[prefab][skin_name] = idx
    end
    
    self:Set("unlocked_skins", unlocked_skins)
    self:Set("unlocked_skins_ids", unlocked_skins_ids)
end
```

**Key pattern:** Maintains dual tables (linear list + indexed map) for efficient lookup and iteration of unlocked skins.

## 7. Summary of Reusable Patterns for Tu-Tiên Mod

### Most Valuable Architectural Patterns

1. **Prefab Loader with Manifest** (`atbooks_all_prefab_loader.lua`):
   - Use `kleiloadlua()` to load many prefabs dynamically from a manifest list
   - Return multiple prefabs per file via `unpack()`
   - Scale to 700+ files without hardcoding

2. **Component Hooking at Scale** (`04_origin_components_hook`):
   - `AddComponentPostInit()` for clean auto-injection of custom data components
   - `AddSimPostInit()` for Map/World-level overrides
   - Use `debug.getupvalue/setupvalue` for internal function interception (with depth guards)

3. **Building/Recipe Registration Pipeline**:
   - Wrap `AddRecipe2()` in a `TBAT.RECIPE` class for DRY principle
   - Separate recipe filters by category (building/decoration/item)
   - Auto-generate placers via `MakePlacer()` from recipe data

4. **Container + Workable Integration**:
   - Register container widget **once** in `require("containers").params`
   - Initialize component on server, listen to replica event on client
   - Use `ListenForEvent("TBAT_OnEntityReplicated.container", ...)` for client-side setup

5. **Skin System for Prefab Variants**:
   - Define skins with `server_fn` / `server_switch_out_fn` / `placer_fn` callbacks
   - Register via `TBAT.SKIN:DATA_INIT()`
   - Use `unlock_announce_data` for unlock UI feedback

6. **Data Persistence Components**:
   - `tbat_data`: Generic key-value store with `Get/Set/Add` and `OnLoad/OnSave` hooks
   - `tbat_com_client_side_data_replica`: Bridge for server-requested client-only data
   - `tbat_com_skins_controller`: Dual table (linear + indexed) for efficient skin tracking

- **Building Variants:** Leverage skin system for cultivated/uncultivated state with different animations/effects
